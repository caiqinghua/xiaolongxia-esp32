## 现有存储限制

`partitions/v2/32m.csv` 的 `assets` 是一个 16 MiB 分区，位于 `0xA00000`。
两个固件 OTA 分区不为模型、字体或表情提供备用副本。
AFE、唤醒词和显示组件会借用映射内存，不能在运行中原地替换这些数据。

`self.assets.set_download_url` 不在组合模式注册，启动资产检查也不会执行遗留 URL。
其他 profile 的下载行为没有在此次更改。没有修改出厂分区表或开启实验开关。

## 签名清单

外层 JSON 与固件发布相同，只有两个字符串字段 `payload` 和 `signature`。
签名是 Ed25519，对以下字节签名：

```text
audream-asset-release-v1\n + UTF-8(payload)
```

其中 `\n` 为单个换行字节。独立签名域禁止将固件清单直接作为资产清单重放。
公钥由调用方的可信固件配置提供，不能从下载的 JSON 获取；没有配置生产密钥。
内部 payload 必须恰好包含以下 12 个字符串字段：

| 字段 | 含义 |
| --- | --- |
| `schema` | 固定 `audream-assets-v1` |
| `format` | 固定 `mmap-v1`，沿用现有资产生成器 |
| `model` | 与运行固件可信设备型号相同 |
| `version` | 可读资产版本，不用字符串排序判断升级 |
| `sequence` | 独立资产发布序号，1–2147483647，必须高于已确认序号 |
| `size` | 精确文件长度，最多 16 MiB；实际可安装大小还需存储布局预检 |
| `sha256` | 完整文件摘要，小写十六进制 |
| `url` | HTTPS，禁止用户凭证、query 和 fragment |
| `firmware_min` | 允许加载此资产的最小固件发布序号，包含端点 |
| `firmware_max` | 允许加载此资产的最大固件发布序号，包含端点 |
| `sr_abi` | 与固件可信 ESP-SR 模型 ABI 标识完全一致 |
| `wake_model` | 与固件所需模型名完全一致，如 `wn9_xiaolongxiaolong_tts` |

`sr_abi` 是发布兼容性声明，不是从不含完整 ABI 信息的模型二进制中自动推导的证明。
发布者必须依据所用 ESP-SR 版本、目标芯片和实际验证定义该标识；签名正确不证明模型能正常唤醒。
兼容性范围亦须经过目标固件验收，不能为了通过检查随意扩大。

## 校验与发布工具

`asset_release::Verify` 在独立签名域下复用固件的有界 JSON/十六进制/数字验证。
`ValidateBundle` 先校验精确长度和 SHA-256，再检查 mmap 头、校验和、表项边界、重复名称、
`index.json` 版本和模型文件引用，最后验证 ESP-SR 模型表及实际存在的指定唤醒模型。
JSON 索引最多 64 KiB、嵌套深度 16；资产表最多 1024 项。
`srmodel_load` 没有长度参数，不能用“加载后再检查”替代这些校验。

工具只签已经生成的文件，不构建固件、不生成模型、不烧录：

```sh
uv run --with cryptography python tools/firmware_release/sign_asset_release.py \
  --image /absolute/path/assets.bin \
  --key /secure/path/asset-release.pem \
  --model esp32-s3-touch-amoled-2.06 \
  --version 1.0.0 --sequence 1 \
  --firmware-min 1 --firmware-max 1 \
  --sr-abi esp-sr-2.3.0-esp32s3 \
  --wake-model wn9_xiaolongxiaolong_tts \
  --url https://updates.example/assets/1.bin \
  --output /absolute/path/asset-release.json
```

上述地址、序号和 ABI 仅为参数示例，不是可部署的生产配置。私钥必须是已有 Ed25519 PEM，
组/其他用户不能读取；输出已存在时拒绝覆盖。工具先验证资产结构和模型名，再生成摘要和签名。
桌面测试使用固定测试私钥，仅在临时目录生成 fixture，不创建生产密钥。

## 存储状态机与 SDK 适配

`asset_storage::Layout` 根据已验证出厂文件的实际长度划分分区内部空间，不改变 ESP 分区表：

```text
base = align_up(factory_file_bytes, 64 KiB)
bank_span = align_down((partition_bytes - base) / 2, 64 KiB)
bank_capacity = bank_span - 4 KiB

[immutable factory + alignment padding][bank 1][bank 2][unused tail]
```

每个 bank 的最后 4 KiB 保存签名清单，其余区域保存原格式完整资产文件。
两个 bank 均不足一个 64 KiB 单位时拒绝初始化更新存储，候选文件超过 bank 容量则在擦写前拒绝。
原出厂文件始终保留在偏移 0；不支持此布局的旧固件仍能读取原文件。
它不是把 16 MiB 简单分成两个 8 MiB，也不承诺任意出厂资产都留有足够更新空间。

`Store` 是单 owner 串行状态机，不允许复制。启动前通过 `Boot` 选择副本，同一实例重复调用不是再次启动。
实际 owner 仍须保证同一分区只有一个 Store，没有其他写入者；这些类不是可同时运行的两个更新服务。

- `Stage` 只擦写既非已确认、也非当前使用的副本，逐扇区擦除；分片读取合并成最多 4 KiB 写入，
  末段及清单补齐到 16 字节以满足加密 Flash 写入要求，签名摘要和逻辑文件长度不包括填充。
- 数据完整、EOF 正确、Flash 回读验证成功、清单回读验签成功后，调用 owner 的 `before_publish`。
  此 hook 必须与录音抢占/取消原子仲裁。通过后才提交待试用记录，迟到取消不撤销已提交记录。
- NVS 用单个 172 字节 blob 保存布局、出厂文件摘要、已确认/待试用副本、各自序号/摘要和试用标记，
  同时保存已发布的最高序号。序列化有固定格式和损坏检测摘要；SDK 适配 commit 后重新打开并核对完整回读。
- 新候选首次启动前先提交 `trial_started`。之前已标为试用但未确认的候选在下次启动被放弃，
  恢复已确认副本；回退仍核对其签名、身份和当前固件兼容性。已确认副本不兼容/损坏时选择原出厂文件。
- `ConfirmTrial` 只能由真实模型/显示健康检查调用；`RejectTrial` 不释放当前映射、不允许在本次运行中覆盖
  失败副本，必须重启。校验通过、完成下载或普通固件健康标记均不自动等同模型健康确认。
- 回退不会降低最高发布序号；相同或更低序号不能经网络重新安装。受信任回退仅允许 journal 中精确记录的
  序号和摘要，不能靠从 Flash 清单读取一个序号就放宽校验。
- journal 损坏、读取失败、出厂摘要/布局改变或保存结果不确定，会拒绝本次运行中的后续更新，不能偷偷重置
  序号为 0 继续写入。写入结果不确定与“保证未写入”不同；下次启动重新检查实际持久化结果。

`asset_storage::Partition` 使用真实 `esp_partition_read/write/erase_range/mmap` 和 `nvs_*` 接口。
它先验证出厂文件边界与校验和、计算摘要，再构建布局；拒绝错误分区、只读属性或非 4 KiB 擦除粒度。
短期校验映射均由 RAII 释放，不释放已有音频消费者的映射，成功句柄即使为 0 也正确释放。
原出厂资产可包含旧唤醒词，适配层不会因新唤醒词配置不同而擦除它；这不保证旧模型适合新固件，
owner 仍须处理无法恢复语音功能时的明确错误及联合固件/资产升级策略。

journal 摘要用于检测损坏，不是 MAC 或防物理回放机制。当前没有声明已实现受攻击者回滚的 NVS 防护、
生产 Secure Boot/eFuse 策略或完全抵抗擦除 NVS 的降级攻击；这些仍属生产信任配置与实机验收范围。

## 实际启动映射

`Assets::LvglStrategy::InitializePartition` 已使用 `asset_storage::Mapping` 打开资产。
只映射选中副本的精确文件范围，不再为了一个小文件映射整个 16 MiB 分区。
旧的无更新配置仍从偏移 0 读取出厂文件；Emote 路径不做副本选择。

仅在组合模式、所需“小龙小龙”模型配置、有效固件发布身份和以下可信配置均有效时，
才读取更新 journal 并选择已确认/待试用 bank：

- `CONFIG_AUDREAM_ASSET_PUBLIC_KEY_HEX`：独立资产验签公钥，默认空。
- `CONFIG_AUDREAM_ASSET_SR_ABI`：经验证的模型 ABI 标识，默认空。

不从远端清单填写这些设置。空配置不会消费待试用记录，也不会默认复用固件签名公钥。
分区空间不足或不支持更新布局时仍可加载通过校验的出厂文件；损坏的映射不向 SDK 暴露指针。

更新副本最终映射的数据再次按保存的已验签身份验证 SHA-256 和内部结构，而不只依赖之前临时映射的结果。
同一 Mapping 重复 Open 不重新选择/消耗试用状态。模型成功加载后 Pin 映射；即使 owner 析构，
仍保留 SDK 借用的内存直到设备重启。明确拒绝在模型借用期间取消映射。
有待确认资产时，不允许用来源不明的全局缓存模型列表冒充当前副本已加载成功。

## 模型试用健康确认

组合模式的真实助手初始化路径在模型加载、唤醒初始化、语音处理初始化全部成功后，才开始观察当前
已 Pin 的试用副本。初始化失败使本次试用不能再确认，不卸载 SDK 已借用的指针。原安全 guard
未就绪只拒绝助手启动，不将其误记为模型损坏。

当前这条确认路径仅接受严格的纯模型包：两个文件（index 和被引用的模型包），index 只有 version
和 srmodels。含字体、skin、emoji 或额外文件的混合资产不通过模型健康自动确认，仍等待后续显示
资源检查；签名和模型初始化成功不能证明其他消费者已经正常使用这些资源。

Application 复用原时钟事件轮询。固件启动健康确认通过、没有应用错误、唤醒采集仍在运行，且
`WakeInputFeedCount` 持续增加时，才累计连续 30 秒观察。计数仅在实际成功读取 PCM 并调用
唤醒 Feed 后递增，不以定时器或云端授权成功代替采集进展。暂停、抢占、休眠、没有新 PCM 或
超过两秒的调度间隙都会重置观察窗口；时钟倒退使本次试用失败。重复初始化不会缩短或重启门槛。

健康确认写入必须由 Application 任务持有存储电源锁，锁不可用时不写 NVS、重新观察。
确认结果会回读验证，失败或结果不确定不会报告成功。成功后同步当前选中副本的 trial 状态，
映射地址保持不变。未确认副本下次启动回退；写入结果不确定时则根据真实持久化记录恢复。

这是模型初始化和采集活性检查，不是唤醒准确率、AEC 或音质验收。仅 PTT、关闭助手或没有进入
唤醒模式时不会自动确认模型。更新页面现在提供独立于账号和云端授权的本地模型自检；只有用户
明确点击、当前试用副本已成功映射和应用、固件启动健康已确认、音频与存储资源空闲时才会启动。
它不会连接网络、修改助手开关或创建助手会话，也不能借固件 OTA 成功标记跳过模型确认。

真实 AudioService 的准备准入已修正：`PrepareWatchWakeWord` 后可在仍暂停且持有维护权限时，
对同一份模型执行 `PrepareVoiceProcessing`，不再错误要求助手已经恢复。准备不启动采集或修改
助手开关；方法级测试补充了此前 Application 替身测试未覆盖的调用顺序。

离线自检复用这条真实准备路径和独立的 `kModelValidation` 音频会话。Application 持有存储读取锁，
进行最长 35 秒的有界采集，并用实际成功完成唤醒与处理器 Feed 的计数驱动 30 秒健康观察。用户
可以取消并稍后重试；本地录音可以抢占自检，旧代次不能释放新录音的资源。初始化、采集、持续
Feed 或清理失败都会保留试用状态为失败；页面提供显式“重启并恢复”，由下次启动选择旧副本，
不在运行时热切换 SDK 已借用的模型指针。资源应用失败同样不会确认试用副本。

## HTTP 下载与共用控制器

`asset_update::Client` 使用工程原 `Http` 接口和已启动的 `asset_storage::Store`，不自行创建第二份
journal 状态。更新 owner 必须在 worker 存活期间独占 Store，并持有网络、TLS 时钟及存储电源资源，
结束并 join 后再恢复模型健康轮询等 owner 操作。Application 已通过当前 Mapping 的独占会话实例化资产客户端。

- `Store::VerifyCandidate` 复用相同的可信兼容性、公钥、最高发布序号、bank 容量及 pending 限制。
  HTTP 检查不写 Flash；安装在 HTTP 打开前重新验证固定清单，避免过期确认绕过更新状态变化。
- 清单只接受 HTTPS、200 和已知且有上限的精确长度；204 必须零长度且没有实际 body。
  拒绝重定向状态、缺失长度、截断、额外内容、错误签名/型号/版本。使用 15 秒 I/O 超时，
  打开、等待响应头、读取和验签后检查取消；此超时不是整个文件的总下载时限。
- 文件只从已验签清单 URL 下载，必须 200 且长度等于签名长度。直接流式调用 Store.Stage，
  不将完整模型包读入 RAM。进度最高 99%；只有 journal 发布成功由控制器报告 100% 和需要重启。
  文件损坏、取消、网络错误及发布结果不确定都保留原副本；跨越提交准入后的取消不伪造撤销。
- `watch_update::Controller` 仍是同一个控制器，检查结果保留固件/资产各自的私有 Verified 类型，
  并与该控制器的固定 target 匹配；拒绝拿固件清单确认模型更新，反向同样拒绝。原固件调用默认
  target 不变，继续复用确认有效期、工作器 join、取消、提交保护与资源故障状态。
- 控制器中的既有 `boot_selected` 对模型 target 表示已经发布下次启动选择，而非调用
  `esp_ota_set_boot_partition`；UI 已按 target 展示，不把模型更新称为固件分区更新。

桌面测试编译真实 HTTP 客户端、Store、分区/NVS 适配和共用控制器；HTTP 与 SDK I/O 为受控替身。
覆盖 22 种清单结果、20 种安装结果及三种控制器目标匹配场景，不代表真实网络/TLS 或设备验收已完成。

## Application 与手表页面

同一“软件更新”页面提供“固件”和“模型与资源”组件选择。选择仅向 Application 提交切换请求，
不自动连接网络、不自动下载；等待 owner 的真实状态再更新选择器。检查、取消、确认安装与重启
均携带 target，确认还核对请求 ID、尝试代次和发布序号。目标不同，即使版本号相同也不能安装；
UI 快速取消入口同样核对 target，不能在后续拒绝请求之前先取消另一个组件的任务。

模型目标使用 `CONFIG_AUDREAM_ASSET_MANIFEST_URL`，默认空，仅允许 HTTPS。
它是受信任的清单入口配置，不替代已有资产公钥、型号、ABI 和兼容性验证，也不是新生产 API 已部署。
可用模型更新前仍须配置此地址及独立资产信任配置；缺失时明确不可用。

Application 复用原按需联网、TLS 时间、电量、录音/助手交接和两分钟确认有效期。取得存储电源锁后，
通过 `Assets::BeginUpdate` 获取当前 Mapping 的 `UpdateSession`；只有一个 session、一个 Store。
worker 运行时，UI/owner 只读取缓存的选择、版本和状态，不并发访问 Store；模型健康操作也不触碰
被 worker 独占的状态。只有工作器 join 后才销毁 session、归还 Store，再释放存储与网络资源。
